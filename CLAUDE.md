# Lukyanov Hydraulic Integrator — Godot simulation

Simulation of a 1D Lukyanov hydraulic integrator (Soviet water-based analog computer, 1936).
Purpose: a digital twin of a home-built rig (5 vessels + movable tank + constant-level outlet),
used to compare simulated water levels against real measurements from timelapse footage.

## Stack
- Godot 4.7, GDScript only, statically typed (`:=`, typed params/returns).
- Viewport 1920×1080, stretch `canvas_items` + aspect `keep` (Steam Deck 1280×800 scales down with bars), `gl_compatibility` renderer.
- Indentation: tabs (Godot default).
- Code comments are in Russian; keep it that way.
- UI is bilingual (ru/en) via `i18n.gd` (`class_name I18n`): write UI strings in Russian wrapped in
  `I18n.t("…")` and add the English to `I18n.EN` (missing keys fall back to Russian). Language:
  `-- --lang=en|ru` launch arg > `user://settings.cfg` > system locale; toggled by L / the language button.
  After adding a new `class_name`, run `godot --headless --path . --import` to refresh the class cache.

## Structure
- `project.godot` — main scene `res://syringe_rig.tscn`.
- `main.tscn` — original abstract view: `Node2D` "Main" with `lukyanov_integrator.gd`.
- `lukyanov_integrator.gd` (`class_name LukyanovIntegrator`) — model, input, CSV logging, and `_draw()` rendering.
- `syringe_rig.tscn` / `syringe_rig.gd` — extends `LukyanovIntegrator`; DIY build scheme from 60 ml syringes
  (vessels), 3-way stopcocks, IV drip lines with roller clamps (resistances), bottle tank on a stand.
  Derives `vessel_height_cm` from syringe volume/diameter, shows levels in cm and ml, parts list,
  Poiseuille estimate of open-line t½. Overrides `_draw()` and wraps `_unhandled_input()` for F1.
  Layout for 1920×1080: part sizes ×`U` (1.35), fonts `FS_SMALL`/`FS`/`FS_BIG` (20/24/30). Long how-to text lives in the F1 manual, not on screen.
- `docs/instruction_ru.pdf`, `docs/instruction_en.pdf` — build/calibration/calculation manual (A4 landscape).
  Generated by `docs/build_instruction.py` (reportlab + pypdfium2, Arial from C:/Windows/Fonts); every text is
  an `L(ru, en)` pair and `f()` formats numbers per language. It also renders `docs/pages/<lang>/page_N.png` at 1054 px height (viewport minus hint line); F1 in `syringe_rig` shows those PNGs (Godot can't render PDF).
  After editing the text or rig defaults, rerun the script — its constants mirror `syringe_rig.gd` defaults.
  `FONT_K` scales all font sizes (2.0). Title image = `docs/scheme_<lang>.png` (also used in README):
  `godot --path . --write-movie x.png --fixed-fps 2 --quit-after 400 -- --lang=en` and take the last frame.

## Model
- Each vessel = one layer of the heated body; water level = temperature.
- Update: `dh_i/dt = (h_{i-1} − 2·h_i + h_{i+1}) / τ` (discrete heat equation).
- Boundaries: left = `tank_level_cm` (movable tank), right = `outlet_level_cm` (constant-level drain).
- `τ = 2 · pair_half_time_s / ln 2`; `pair_half_time_s` comes from calibrating the real rig
  (time for the level difference between two neighbouring vessels to halve).
- Explicit Euler, sub-stepped so `dt/τ ≤ 0.2` (stable limit is 0.5). Levels clamped to `[0, vessel_height_cm]`.
- Steady state with a constant tank must be a straight line — use as a sanity check after changes.

## Data
- `S` key writes `user://lukyanov_levels.csv`: `t_s,tank_cm,h1_cm..hN_cm`, one row per `record_interval_s`.
- This CSV format is what real measurements are compared against — don't change columns without reason.

## Controls
↑/↓ tank ±1 cm · Space pause · +/− sim speed ×2 · R reset · S save CSV · L language.
F1 manual overlay (←/→, PgUp/PgDn, wheel or click to flip, Home first page, O open PDF externally, Esc/F1 close).
Mouse (`syringe_rig`): drag the tank bottle, the drain tube end, or inside a syringe (sets its level);
wheel = ±0.1 cm on those; top buttons for pause/speed/reset/CSV/manual. Positions come from
`make_input_local(event)`, so tests can feed synthetic `InputEventMouse*` straight into `_unhandled_input`.

## Tests
- `tests/run_tests.gd` — headless suite (physics, mouse, language/manual pages, CSV format):
  `godot --headless --path . --import` then `godot --headless --path . -s tests/run_tests.gd` (exit 0 = pass).
  Add a check there for every new feature; keep it render-free (no screenshots) so it runs in CI.
- Git ignores `*.import`; after switching branches delete stale `docs/pages/*/*.png.import` without a PNG,
  otherwise Godot still "sees" removed manual pages.

## CI and releases (GitHub Actions)
- `.github/workflows/ci.yml` — on every PR and push to `main`: Godot 4.7.1 (Linux) + Windows export templates
  (`.github/actions/setup-godot`, cached), then `.github/scripts/test_and_build.sh`: import → tests →
  `--export-release "Windows Desktop"`. The test `.exe` is attached to the run as an artifact (7 days).
- `.github/workflows/release.yml` — when a PR is **merged into `main`** (the default branch; there is no `master`):
  bumps the version from the latest `vX.Y.Z` tag, writes it into `application/config/version`, re-runs
  tests + export, zips `LukyanovIntegrator.exe` + both PDFs + README, creates tag `vX.Y.Z` and a GitHub Release.
  First release (no tags) is `v0.1.0`.
- Export preset: `export_presets.cfg` → "Windows Desktop", single exe (`embed_pck`), `modify_resources=false`
  (no rcedit/wine needed on Linux). The game shows the version top-right ("dev" in the repo).
  In the exported build the O key opens the PDF next to the `.exe` (`_help_pdf_path()`).

### Release rules for Claude
- Never create tags or releases by hand and never edit `config/version` in `project.godot` — it stays `"dev"`;
  the release workflow owns both.
- Work on a branch and open a PR into `main`; every merge publishes a release, so pick the bump with a PR label
  when creating the PR (`gh pr create --label …`):
  - `release:major` — incompatible change: CSV columns, scene/parameter renames, rig redesign;
  - `release:minor` — new feature (new control, model term, manual section/problem);
  - no label — patch: fixes, text/translation edits, CI tweaks;
  - `release:none` — merge without a release (docs-only or repo housekeeping).
  Say in the PR description which bump was chosen and why.
- Before opening a PR run the tests locally; if the manual text or rig defaults changed, rerun
  `docs/build_instruction.py` and commit the PDFs and pages too (CI does not regenerate them — it needs Windows fonts).
- After merging, the release appears at https://github.com/avv123avv/lukyanov_integrator/releases;
  if the Release workflow fails, fix it on a new branch/PR — do not re-tag by hand.

## Conventions
- Keep the physics (`_step`, `_tau`) independent from rendering so it can be moved to a separate
  class or tested headless later.
- Exported vars are the user-facing tuning knobs; keep defaults matching the physical rig.
- Run: open in Godot 4.7 and press F5. Headless check: `godot --headless --path . --quit`.
